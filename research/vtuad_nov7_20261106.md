## What was built
- src/make_synthetic_vtuad.py: same backgrounds (same seed, same 1500/site —
  site lists pair exactly with the original set), same share prior, same
  energy-domain mixing, same held-out sites (Fish Hoek, Sea Point), disjoint
  clips train/val (every 5th). Two datasets: `_large` (221-clip pool:
  9,000 train / 543 val rows) and `_all` (487-clip pool, same sizes).
- src/train_vtuad.py: 30 features (identical to the real-only baseline — NO
  absolute-level features; v2's 86-feature set just failed publicly), same
  LightGBM params, 10 seeds [7..41], 600 rounds, no calibration.
  Per-seed checkpoints (resume-safe). Two candidates trained:
  (a) full large-only: hms 5,797 + vtuad 9,000 train rows;
  (b) balanced: hms 5,797 + vtuad 2,000 train rows (cap test).

## Interpretation
- Adding VTUAD rows HURTS honest hms validation by ~0.006, and the balanced
  cap (26% VTUAD) costs exactly the same as the full mix (61% VTUAD) —
  so it is NOT a dilution/weighting issue. The mere presence of the VTUAD
  distribution shifts the model's splits enough to cost -0.006 on hms
  mixtures, and VTUAD mixtures themselves are harder for these 30 features
  (0.901 vs 0.9175 on the same model). The 30 relative features cannot fit
  both vessel distributions at once.
- The `_all` variant (adds tug/fishing/pleasurecraft) was built but NOT
  trained: same mechanism, even further spectra — no reason to expect a
  pass, and slots are precious.
- Caveat (v2 lesson cuts both ways): validation does not predict public.
  A val-worse model could still help publicly IF the test set contains large
  vessels. But there is no positive evidence for that here — only a val
  loss — so neither candidate is recommended for a Nov 7 slot on current
  evidence. The files exist, verified, if the parent wants to overrule.
